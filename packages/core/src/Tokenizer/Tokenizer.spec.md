## Intent

Tokenizer lets a person build and edit a set of searchable values as removable
tokens around one stable combobox input. It owns the field surface, token/input
layout, suggestion-menu relationship, and the package-internal identity needed to
open a related surface from the control where the task began.

This record preserves shipped Tokenizer facts and defines three component-owned
contracts: one package-internal opening-control descriptor for Core peers, the
post-selection lifecycle of an empty-query bootstrap menu, and an experimental
touch presentation in which a trigger opens one searchable modal bottom sheet in
place of the inline combobox. The descriptor lets Layer prepare placement without
exposing DOM refs, pointer coordinates, or width policy to consumers. The
dependent [PowerSearch draft](https://github.com/facebook/astryx/pull/5804)
remains evidence for the need, not authority for this record.

Where the shipped Tokenizer does not yet meet a requirement, the row carries a
present-tense implementation gap note.

## Compatibility and migration

- The stable public API and the default `hasEntriesOnFocus={false}` path are
  unchanged.
- Compatibility class: intentional behavior correction for the existing opt-in
  `hasEntriesOnFocus` mode. A committed selection from its current empty-query
  bootstrap cohort keeps the remaining eligible loaded choices available instead
  of closing the menu after every choice.
- Controlled/uncontrolled ownership is unchanged. Retention follows committed
  controlled values; a proposed value that the caller has not accepted remains
  available.
- Experimental surface (DEC-3): the touch sheet presentation is the
  `presentation` option inside the optional `experimental` prop object, outside
  the stable compatibility promise (`spec:AST-017/FR21`). Omitting `experimental`,
  or omitting `presentation` inside it, keeps the inline combobox and its
  anchored suggestion menu on every device. Changes to the option ship as
  `[experimental]` patch releases (`spec:AST-017/FR22`).
- Migration decision: none. Existing callers that omit `hasEntriesOnFocus`, typed
  search selection, explicit dismissal, disabled state, maximum-entry state, and
  source-loading behavior retain their prior boundaries.

Consumer migration instructions belong in consumer docs and release notes.

## Ownership boundary

**Owns**

- The token collection, stable native search input, and painted outer field/control
  surface that contains them.
- The lifecycle of Tokenizer's own focus-bootstrapped suggestion menu after a
  committed selection, including selected-value exclusion, next-option choice,
  focus continuity, and terminal close states.
- The active opening control for a task initiated within Tokenizer: the inner input
  for add/search work or the actual activated token/control for edit work.
- The identity, usability, lifetime, and safe fallback semantics of those elements
  in one package-internal descriptor.
- Tokenizer's current suggestion-menu width and minimum-anchor-width behavior.
- Token wrapping and the `none`, `unfocusedInline`, and `unfocusedLayer` overflow
  presentations.
- The touch sheet presentation: its trigger, the single searchable sheet, the
  in-session row order, progressive long-list rendering, the create row, the
  confirmed Clear all, and which Tokenizer props the sheet honors.

**Does not own / non-goals**

- General BaseTypeahead selection policy. Direct single-select BaseTypeahead and
  Typeahead keep their select-clear-close-refocus lifecycle.
- A new rule for typed-query selection or a requirement to refetch suggestions
  after each Tokenizer selection.
- General anchor positioning, top-layer hosting, viewport collision, generated
  anchor names, or prepared-placement lifecycle — owned by
  `architecture:layer-runtime`.
- PowerSearch editor sizing, including its proposed 400–720 CSS px range — owned
  by `component:PowerSearch` if that draft is approved.
- A public input ref, opening-control ref, anchor descriptor, maximum menu width,
  coordinate, placement, or pointer-tracking API.
- A change to released `menuWidth` semantics. It remains an exact preferred pixel
  width whose rendered menu does not shrink below the Tokenizer outer field.
- Consumer-provided token content and visuals. Tokenizer owns only the capture
  boundary needed to identify the control that activated an internal open.
- The compact-touch resolution rule behind `adaptive`, owned by
  `spec:AST-094/FR13` (a touch presentation applies under a coarse primary
  pointer, after hydration; compact is `spec:AST-012/FR9`). Tokenizer resolves
  `adaptive` with that one rule, as the selection controls do; it adds no
  query of its own.
- The sheet's dialog, scrim, gestures, snap behavior, and dismissal paths —
  owned by `component:BottomSheet` and `family:overlay-dismissal`; its
  on-screen keyboard behavior — owned by `spec:AST-099`.

## Public concepts

One public concept is introduced, as an experimental surface: the optional
`experimental` prop object and its `presentation` option, `'popover' |
'bottom-sheet' | 'adaptive'` (DEC-3). The option type is inlined on the prop;
no experimental hook or type is exported. Declarations carry `@experimental`
and consumer docs carry `stability: 'experimental'` metadata. Existing
consumer props and usage remain in `Tokenizer.doc.mjs`. The existing
`hasEntriesOnFocus` mode includes the component-owned post-selection behavior
in FR13–FR15.

In the sheet presentation the trigger is the control: `ref`, `id`, `data-*`,
`aria-*`, and the other base props reach it (`family:input-fields/FR10`,
`architecture:public-component-api/INV8`), `handleRef.focus()` and `blur()`
act on it, and `onFocus`, `onBlur`, and `onKeyDown` report its events. The
`ref` type follows the opt-in. The exported `TokenizerProps` remains an
interface and keeps `ref?: Ref<HTMLInputElement>` as released, so `interface
X extends TokenizerProps<T>` and `Omit<TokenizerProps<T>, …>` wrappers keep
compiling; the component's own parameter type is where the widening lives:
with `experimental` passed, `ref` accepts `Ref<HTMLInputElement |
HTMLButtonElement>` and receives the trigger button in the sheet presentation
and the combobox input otherwise. Implementation gap: `ref` is typed
`Ref<HTMLInputElement>` whether or not `experimental` is passed. The
props that describe the inline combobox have no surface in the sheet
presentation: `renderItem`, `renderToken`, `endContent`, `hasClear` (the
sheet's own Clear all replaces it), `hasEntriesOnFocus` (the sheet always
lists the bootstrap set), `menuWidth`, `tokenOverflowBehavior`, and
`hasAutoFocus`. Passing one of them with the sheet presentation emits one
development-mode warning naming the prop, so it is not silently dropped
(`architecture:public-component-api/INV3`); every other prop keeps its
meaning.

The descriptor is package-internal. It must be absent from exported
`TokenizerProps`, public barrels, generated declarations, consumer docs, CLI
output, and Changesets. Current `handleRef` remains the public focus/blur handle;
it does not become an element or geometry escape hatch.

### Allowed variation

- **AV1 — Token presentation.** Default Token controls and custom `renderToken`
  content may differ visually. The opening-control capture boundary remains
  Tokenizer-owned when an identifiable descendant control initiates activation.
- **AV2 — Overflow presentation.** Tokens may wrap normally, truncate while
  unfocused, or move with the live input into `unfocusedLayer`. These modes may
  change element geometry but not descriptor identity or fallback order.
- **AV3 — Internal representation.** The descriptor may use refs, elements,
  callback registration, or an equivalent Core-private representation. It must
  preserve FR4–FR8 and stay out of public declarations.
- **AV4 — Layer mechanism.** Layer may realize the latched edge through a
  zero-size marker, separate size and position anchors, or another internal
  mechanism that satisfies FR9–FR12 and current Layer architecture.
- **AV5 — Responsive movement.** CSS may follow outer-field movement, container
  resize, writing direction, and collision while open. JavaScript does not
  remeasure or select a new preferred edge until the next open.
- **AV6 — Internal retention mechanism.** Tokenizer and BaseTypeahead may retain,
  project, or otherwise coordinate the settled cohort through a package-private
  mechanism. That mechanism must preserve FR13–FR15, must not become public API,
  and must not change direct single-select BaseTypeahead behavior.
- **AV7 — Sheet surface composition.** The sheet presentation may compose
  BottomSheet, the shared panel search field, EmptyState, AlertDialog, and the
  checkbox indicator in any internal structure, and may load that surface on
  demand, provided FR16–FR24, AR6, and PR6 hold and the structure stays within
  `architecture:component-style-authoring` INV7 — minimal DOM, content
  rendered once; at rest, a pointer-specific presentation is a change of
  attributes and styles on the same elements; open, in INV7's words, "the
  open layer under a coarse pointer has at most as many elements as under a
  fine pointer (beyond that, only by the open-layer allowance `spec:AST-017`
  FR60 and DEC-29 set)". The closed `adaptive` trigger (a different element,
  which no allowance covers) and the open sheet (more than the five extra
  elements FR60 allows) are owner exceptions DEC-3 records, beyond that
  allowance, with their before and after counts.

### Transformation and precedence order

- **ORD1 — Surface width.** Resolve the consuming component's preferred surface
  width. Tokenizer contributes no PowerSearch width value.
- **ORD2 — Full-width decision.** If the preferred surface width is greater than
  or equal to the outer field width, use the outer field and logical start. Do not
  read or apply opening-control geometry to choose an edge.
- **ORD3 — Opening control.** For a narrower surface, use the actual captured
  token/control when available; otherwise use the stable inner input; otherwise
  use the outer field at logical start.
- **ORD4 — Edge selection.** Compare the usable control with the outer field's
  physical start and end, choose the nearer edge, and map it to logical
  start/end. A tie resolves to logical start.
- **ORD5 — Hidden commit.** Commit width mode, anchor, and alignment while hidden;
  show on the next animation frame and latch the result until close.
- **ORD6 — Collision.** Apply Layer's CSS-owned viewport and safe-area collision
  behavior last. Collision does not reopen the semantic edge decision.

### Performance and resources

- **PR1 — No render-time measurement.** Neither Tokenizer nor a descriptor
  consumer may read geometry during React render.
- **PR2 — One read batch per open.** Open preparation reads the outer field and,
  only when needed, the opening control in one batched read phase. Instrumented
  verification must fail on a second preparation batch for the same open.
- **PR3 — Hidden preparation.** Anchor, width mode, and alignment commit while the
  surface is hidden; show occurs on the next animation frame. Close or unmount
  before that frame cancels the pending show.
- **PR4 — No continuous tracking.** The contract adds no pointer tracking,
  always-on ResizeObserver, global resize listener, or repeated geometry read.
- **PR5 — CSS owns ongoing geometry.** Container resize, outer-field movement,
  writing-direction layout, and final collision remain CSS/Layer work after the
  one-time semantic choice.
- **PR6 — The sheet surface is opt-in cost.** A field in the `popover`
  presentation does not load the sheet surface's code; the surface loads on
  demand only while a field resolves to `bottom-sheet`, renders nothing on the
  server or during the hydrating render, and renders its long lists in batches
  (FR21). Implementation gap: no sheet surface exists.

## Accessibility contract

AR1–AR5 describe the `popover` presentation; AR6 describes the sheet
presentation.

- **AR1 — Modality equivalence.** The same input or token/control produces the
  same preferred placement for pointer, touch, keyboard, and programmatic
  activation. No pointer coordinate participates.
- **AR2 — Semantic stability.** The descriptor and placement work MUST NOT change
  Tokenizer's field, group, combobox, listbox, option, token, announcement,
  disabled, focus, or dismissal semantics.
- **AR3 — Focus stability.** Existing focus/refocus behavior survives add,
  remove, clear, overflow expansion/collapse, and related-surface open/close.
- **AR4 — No visible placement error.** A person MUST NOT see a surface first
  paint at an outer-start or stale position and then jump to its resolved edge.
  Invalid identity falls back before show rather than flashing or showing wrong.
- **AR5 — Retained combobox semantics.** While a focus-bootstrapped menu remains
  open after selection, DOM focus MUST stay on the combobox, `aria-expanded` MUST
  remain true, and `aria-activedescendant` MUST name the rendered next valid
  option. Closing for dismissal, disabled, maximum, or exhaustion MUST remove the
  active descendant. Selected and disabled options are never interactive.
- **AR6 — Sheet semantics.** In the sheet presentation the trigger is a button
  named by the field label with `aria-haspopup="dialog"` and `aria-expanded`,
  and its accessible description is everything the inline input's is, in
  the inline input's order — the caller's `aria-describedby` ids, the field
  `description`, the status message, and the `disabledMessage` reason when
  disabled (a disabled control exposes its description and its reason on
  itself, `spec:AST-085/FR5`) — followed by the selected count and the
  selected token labels, so the selection the sighted person sees is exposed
  to assistive technology as the trigger's description; the labels are the
  rendered tokens themselves, each referenced by id from `aria-describedby`
  after a hidden count, so no label renders twice
  (`architecture:component-style-authoring` INV7); whether a screen reader
  reads a description with the button depends on the screen reader
  (`spec:AST-009/FR8`), and the DOM and accessibility tree prove the
  `aria-describedby` exposure (WCAG 2.2 SC 1.3.1 and 4.1.2 through
  `spec:AST-020/FR1`);
  the sheet is a modal dialog named by the field label; the search field is
  named `Search {label}` with a named clear action; each row is a `checkbox`
  named by its item label with `aria-checked`, toggled by tap or click and by
  Space and Enter, the activation keys of the native button it is rendered on
  (`spec:AST-020/FR15`; WCAG 2.2 SC 2.1.1 and 4.1.2); disabled rows and a
  disabled trigger use `aria-disabled` and keep their focus order; while the
  sheet is
  open, additions, removals, a confirmed Clear all ("All items removed", made
  once the confirmation has closed, since a message sent while the
  confirmation covers the sheet is not heard — `spec:AST-086/FR14`), the
  search's busy start, and how each search
  ended — the result count for a non-empty query, or the empty state's text
  when it shows — are announced once per occasion from inside the sheet
  through `useAnnounce`, which `spec:AST-086/FR14` routes into the persistent
  polite container of the sheet's own dialog while it is open, because the
  shared page-body channel is not exposed behind a native modal; the
  container follows FR3, FR5, and FR6 of that record (WCAG 2.2 SC 4.1.3
  through `spec:AST-020/FR1`). After the sheet closes focus returns to the
  trigger and the field's announcements follow the same FR14 route from
  wherever the field renders.
  Implementation gap: no sheet exists.

## Decision log

### DEC-1 — Opening control is package-internal and read once per open

**Reference:** `component:Tokenizer/DEC-1`
**Decider:** `cixzhang`, `2026-08-31`

Tokenizer provides Core peers a package-internal descriptor for stable outer-field
and active opening-control identities. A consuming surface resolves its preferred
width first: a surface at least as wide as the field aligns to the outer field at
logical start; only a narrower surface may choose the nearer outer physical edge
from a usable opening control, with logical start as the tie and safe fallback.
The choice is modality-neutral and latched for one open lifetime.

Open preparation reads the outer field and, only when needed, the opening control
in one batch, commits width mode, anchor, and alignment while hidden, shows on the
next animation frame, and performs no continuous tracking. Tokenizer's public API
remains unchanged. Implementation must provide real-Chromium open-state evidence
for full-width and narrower placement, LTR and RTL, constrained collision, stale
fallback, and the first paint without a visible jump.

### DEC-2 — Focus bootstrap supports consecutive committed selections

**Reference:** `component:Tokenizer/DEC-2`
**Decider:** `cixzhang`, `2026-09-19`

When `hasEntriesOnFocus` is enabled, committing a choice from the current settled
empty-query bootstrap cohort keeps the popup open with the remaining eligible
loaded choices. Committed values are excluded by `SearchableItem.id`; distinct
items with the same label remain eligible. The option after the committed choice
in displayed order becomes active; when there is no following choice, the nearest preceding choice becomes active. Input focus and valid combobox/listbox
ARIA relationships remain intact.

The popup closes and clears its active descendant when no eligible loaded choice
remains, `maxEntries` is reached, the control becomes disabled, focus leaves, or
the person dismisses it. Pending or stale source work cannot reopen a terminal
popup or make stale choices interactive. This decision adds no public API, does
not require a refetch, and does not change typed-query selection or direct
single-select BaseTypeahead behavior.

### DEC-3 — The touch sheet presentation is an experimental option

**Reference:** `component:Tokenizer/DEC-3`
**Decider:** `imdreamrunner`, `2026-10-23`

Tokenizer offers its touch surface through the `presentation` option of the
optional `experimental` prop object, with the values `popover`, `bottom-sheet`,
and `adaptive` that the selection controls use. The option is marked
`@experimental` in declarations and `stability: 'experimental'` in authored
docs, so it may change or be removed in a patch release (`spec:AST-017/FR21`).
Omitting `experimental` keeps the inline combobox on every device. `adaptive`
resolves through the shared compact coarse-pointer policy, so a Tokenizer and a
Selector on the same page switch together. The value set is the selection
controls' `AdaptivePresentation`, because Tokenizer picks several items from a
searchable list as MultiSelector does. Rejected: the date and time fields'
`PickerPresentation` value set with `adaptive-bottom-sheet` (its native-picker
axis has no counterpart here). The sheet's parts expose no Tokenizer theming
targets while the option is experimental (`spec:AST-017/FR27`); sheet targets
follow the option's promotion.

The sheet surface is one tall modal BottomSheet opened by a trigger that shows
the selected tokens: a search row on top, checkbox rows whose order is fixed
while the sheet is open and regrouped selected-first on the next open,
progressive rendering of long lists, a create row with a trailing Add action,
and a footer with a confirmed Clear all and Done. The sheet is a standalone
BottomSheet driven by `isOpen`. Rejected: switching surfaces automatically on
`pointer: coarse` without an opt-in (changes stable behavior). Rejected: a
top-level stable `presentation` prop before the surface has consumer evidence.
Rejected: separate manage and add sheets (two near-duplicate lists; the person
loses their place). Rejected: hosting the one sheet in a BottomSheetSwitcher.

**INV7 owner exception** (`architecture:component-style-authoring` INV7;
`spec:AST-017/FR60`), in two parts, both beyond the FR60/DEC-29 allowance —
which admits an open layer five extra elements and a closed control none —
and recorded here with their measured counts as FR60 asks. _The closed field under `adaptive`._ INV7's
surface budget says a pointer-specific presentation is a change of attributes
and styles on the same elements; under `adaptive` on a compact coarse-pointer
client the closed field instead renders a different element — the trigger
button showing the selected tokens — in place of the inline combobox input,
its token remove actions, and its overflow handling, because the touch surface
is a sheet opened by a button, not a menu anchored to an input (DEC-3, FR16).
The swap removes elements rather than adding them: at rest 154 elements under a
fine pointer against 120 under a coarse one, measured as below, so the coarse
pointer stays under the fine count at rest. _The open layer._ The open sheet
has more elements than the open popover menu it replaces under a fine pointer,
because it is a different surface, not the same one restyled: a full-height modal with a
panel and handle, a search field with its clear action, a list whose rows are
checkbox rows with an indicator and a position, a footer with Clear all and
Done, and the sheet's own live region, in place of an anchored listbox of
plain options; the Clear all confirmation is in the DOM only from the Clear
all press until it closes. Measured in Chromium 149 on the
Experimental: adaptive story (five tokens selected), elements under `body`,
fine = desktop 1280×800 `pointer: fine`, coarse = iPhone 13 profile
`pointer: coarse`. At rest: 154 fine / 120 coarse (the trigger with its tokens
is smaller than the inline field with its token remove actions and input).
Open, at the query "e" — a searching state, so the footer is not rendered
(FR18): 157 fine — the inline field with its anchored menu open on the one
story item matching "e", plus the two shared page live regions the first
announcement creates — and 165 coarse. The coarse total reconciles exactly:
120 at rest, minus the 2 elements of the app-global surfaces host (the
toast host the open modal re-hosts inside itself, `spec:AST-003/FR18`), plus
the sheet's dialog of 47 — BottomSheet's dialog, panel, handle and edge tint
7; the sheet body 2; the search row with its clear action 19; the list 16
(the list element, its scroll host, and two checkbox rows of 7 with indicator
and position); the sheet's live region 1; the re-hosted surfaces host 2. A
pending Clear all confirmation adds 20 while it is open; the footer, shown
only while the query is empty, adds 9. The forced `bottom-sheet` presentation
renders the same elements under either pointer (114 at rest, 165 open at "e",
its dialog 53 with the story's create row of 6). At rest the coarse pointer
never has more elements than the fine one: nothing of the sheet is in the DOM
until a press. The exception covers the closed `adaptive` trigger and the open sheet; its
counts are re-measured when either surface changes.
