# Motion measurements

The one list of UIKit reference captures the touch presentations need. Every
`GUESS` or `webkit` value in `uikit/` names one of these IDs (`@measure`), and
`uikit/uikit.test.ts` fails if a named ID is missing here. When a capture
lands, its values replace the guesses in `uikit/` (tagged
`@source measured: <app>, iOS <version>, <method>, <date>`).

Run everything on the newest iOS simulator runtime (iOS 26.x, and 27.x when
installed); rows marked † also on iOS 18 for the pre-glass delta. iPhone
16-class device, 3× scale, real HID touches with logged timestamps.

## Methods

- **A, animation dump** (exact parameters): an instrumented UIKit app logs
  every `CAAnimation` added to a layer (`-[CALayer addAnimation:forKey:]`):
  view class, key, key path, class, from / to / by, additive, begin time,
  duration, timing-function control points, and for `CASpringAnimation` mass,
  stiffness, damping, initialVelocity, settlingDuration, allowsOverdamping.
  Works for everything UIKit animates in process.
- **B, recording** (ground truth on built-in apps): a 60 fps recording (120
  where available), the moving edge tracked per frame into x(t), fitted to a
  spring (response, damping ratio) or a curve by least squares and compared
  with A.
- **C, per-frame log**: a `CADisplayLink` logger writes time
  (`CACurrentMediaTime()`), the touch stream (`UIWindow.sendEvent`),
  `contentOffset` and the presentation frames / transforms / alphas of the
  views under test, while a UI test drives drags of known velocity
  (`press(forDuration:thenDragTo:withVelocity:thenHoldForDuration:)`).
- **D, read**: print an SDK constant, a computed property or a private
  style-provider value directly (harness or debugger).
- **H, haptics log**: swizzle the trigger methods of `UIFeedbackGenerator` and
  its subclasses (`impactOccurred`, `impactOccurredWithIntensity:`,
  `selectionChanged`, `notificationOccurred:`, and private subclasses' methods)
  and `AudioServicesPlaySystemSound*`; log class, style, timestamp. Record
  audio.

shape the math: every spring UIKit attaches
has `allowsOverdamping` off (clamped to critical) except
`UIView.animate(springDuration:bounce:)`; with it on, Core Animation renders
"overdamped" springs with the two exponentials' coefficients swapped and the
initial velocity's sign flipped, a curve that overshoots. Push and pop are
not Core Animation animations on iOS 26.2: UIKit writes presentation
modifiers every frame from the main thread.

in process, each confirmed with HID touches and the state log; values in
`uikit/gestures.ts` tagged `measured:`): M-G01 to M-G09, M-G11 (the band
only: simulator HID touches carry no edge flag, so an edge pan cannot begin)
and M-G12. Findings that shape the code: the pan's hysteresis applies per
axis and is left out of `translation(in:)`; the pinch measures its scale
from the starting span moved by its hysteresis; the swipe is recognized
during the motion; `velocity(in:)` is 0.2 × the newest event's
instantaneous velocity + 0.8 × the previous one's (it reproduces every value
UIKit reported on six recorded streams), does not decay through a rest and
ignores the lift: the table keeps that one filter and no least-squares
estimator (`spec:AST-100` FR2); a sheet over a scrolled list leaves the whole
drag to the list (no mid-gesture handoff), so the table carries no handoff
slop (`spec:AST-094` FR14).
