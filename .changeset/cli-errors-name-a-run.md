[fix] CLI errors name a run to try. An option a command does not take now names the options the command takes, and the command as meant when the option points at one of them: `component Table --format json` names `component Table --json`, `--full` names `--detail full`, `--props-only` names `--props`, and `theme --list` names `theme list`. A word the CLI has no command for names the command the words point at: a whole command passed as one word, a command's plural, an option some commands take (`list` names `component --list`), a command deeper in the tree (`verify` names `integration verify`; `eject` names `theme eject --help`, since it needs a theme), or a name another command reads (`info Text` names `component Text`); with no such command, it names near command names by Commander's own rule (at most three edits, and more than 40% of the name the same), so `info Text` names `component Text` where it used to name `init`. `doctor` given a path names `doctor --built <path>`, and several paths in the project name the folder that holds them. `upgrade --from <version> --list` names `upgrade --list` and the migration from that version, `template` with `--skeleton` or `--list` and other words names each run alone, and an option given without its value prints the command's usage with that option in it. Every named run parses, and a call that does not itself name the `experimental` group gets no experimental command in its answer. A word that names no command followed by an unknown option (`astryx describe Table --format json`) now reports `ERR_UNKNOWN_COMMAND`, as the same call without the option does, instead of `ERR_INVALID_OPTION`; every other error code, and every exit code, is unchanged.
