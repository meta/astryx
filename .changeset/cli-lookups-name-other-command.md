[feat] `astryx component`, `astryx hook` and `astryx template` now point to the right command when a name they do not find is an entry another lookup command reads, as `astryx docs` already did. One rule serves all four commands. An entry's name is its full id: a component, hook or template id, or a docs route. A name matches the typed name at one of four tiers, best first: exact (the whole name, in any case); folded (the whole name without spaces and hyphens, and a hook with or without `use`); last segment (only the last segment of a path id or docs route, exact or folded); words (the name carries every typed word). When the typed name matches another command's entry at one of the first three tiers, that command joins the suggestions by the entry's full id, such as `astryx hook useHotkeys` for `component use-hotkeys`, `astryx component Button` for `template Button`, or `astryx docs typography/font-setup` for `hook font-setup`. A better tier wins; inside a tier, a component comes before a hook, a hook before a template, and a template before a docs route. The hint goes right after the command's own suggestions that match at its tier or a better one, so it is first only when none does. The list never grows: the last suggestion drops, and a hint that would come last is left out; when a command had no suggestion, the hint is the only one. Every hint names an entry the hinted command reads: a template only when `astryx template` lists it, and any route of the docs tree, namespaces included. The error code and the `{name, reason}` shape stay. Docs keeps its rule that the hint stands alone when no topic shares a word with the name, and `component` keeps its example-block message, which already names `astryx template`. Names that resolve still resolve as before, and a miss stays fast: file names and doc text say first which components, hooks, templates and docs routes can match, so only those are read.
