[feat] `astryx doctor integration validate` (and so `integration check`) lists each component example that is not `kind: 'setup'` but cannot run on its own, the way a docs page or catalog card runs it as a live preview: code that does not compile, such as a top-level `return` or code that stops partway (`example_does_not_compile`); code that renders nothing (`example_renders_nothing`); a name the example never defines or imports (`example_undefined_name`); an import of code that runs only on a server, an async server component it renders, or a read of `process.env` (`example_server_only`); and an import of a relative path or of a package the package does not declare (`example_import_unresolvable`). Each is a note with its fix that fails `integration check --strict --next` now and `--strict` from the next minor release, so no build that passed before fails. An example may use without importing the components its package documents, the components and hooks Core documents, React's exports, and browser globals. `previewableExample(example, scope)` from `@astryxdesign/cli/authoring` is the same rule for a tool that shows examples as live previews: it returns the module to bundle, or why the example cannot run. `integrationExampleScope(pkg)` from `@astryxdesign/cli/api` returns the scope Doctor reads a package's examples with, as JSON, so a catalog can store it and a preview tool read each example exactly as Doctor does. `showcase_not_standalone` now reads the same packages: a Node built-in name such as `events` that only `devDependencies` installs counts as server-only, because an app that installs the package does not get it.
