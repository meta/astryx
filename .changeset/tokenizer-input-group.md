[feat] Tokenizer is now an InputGroup-compatible control (#3520). Inside an `InputGroup` it consumes `InputGroupContext` instead of rendering its own `Field`, so the group owns the single label, description, and status chrome — no more duplicated label or nested field wrapper. The typeahead input is named by the group label plus the Tokenizer's own label (composed with `getInputARIA`, so `aria-describedby` merges the group's description/status with the input-local disabled reason rather than replacing it), and the control adopts the shared `groupStyles.inGroup` border/radius treatment so it joins the group's seam. The group also owns size, the disabled state, and validation: a disabled group disables its Tokenizer, a grouped Tokenizer takes the group's `size` (an explicit larger `size` no longer escapes the row), and its local `description`/`status` are neither referenced from `aria-describedby` nor painted beside the group's status. Because the group is a fixed-height single-line surface, a grouped Tokenizer keeps its tokens on one scrolling row instead of wrapping past the shared border — cap selections with `maxEntries` or summarize them with `tokenOverflowBehavior`. Its end controls (the clear button, `endContent`, and the busy indicator) hold the end of that row: tokens scroll beside them, never underneath. The row hides its native scrollbar and fades whichever edge hides tokens instead; forced colors bring back a thin native scrollbar. Keyboard users reach hidden tokens through their remove buttons (Shift+Tab from the input), and a disabled Tokenizer's row becomes its own Tab stop while it overflows, named by the Tokenizer's label, so the arrow keys can scroll it.
