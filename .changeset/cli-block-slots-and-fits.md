[feat] Block templates say where they go, and page templates say where blocks go. A page template declares `slots`, the named places in it where blocks go, each with a kind from one shared vocabulary (`navigation`, `header`, `toolbar`, `main`, `panel`, `footer`, and the body sections `metrics`, `chart`, `table`, `list`, `form`, `content`, `feedback`, `chat`). A block template declares `fits`, the kinds of place it goes in, best first, or the contexts `overlay` (opens from a trigger) and `inline` (goes inside another piece); an empty list marks a reference block that shows a component's options. Every page and block template Astryx ships declares them. `astryx build` lists the start template's slots (`start.slots`) and names the slot each block it suggests goes in (`slot`), with the block's `fits`; its text prints a `slots:` line for the template and a `slot:` line for each block. `astryx template --list --json`, `astryx template <name> --json` and `--skeleton` carry the fields, the skeleton prints a `# Slots:` or `# Fits:` line, and `astryx template <name>` prints the same on standard error beside the package. `astryx search --json` carries `fits` on block results and `slots` on page results, and `--verbose` prints them. Which blocks and templates build and search choose is unchanged. Integration templates can declare both fields with `@astryxdesign/cli` 0.7.16 or later; `astryx doctor integration validate` notes a package whose peer range admits an earlier CLI, a kind the CLI does not know, two slots with one name, and a slot of a context kind.
