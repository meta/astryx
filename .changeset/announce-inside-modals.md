[fix] `useAnnounce` now delivers a message by where its caller is. Inside an open Astryx modal — a Dialog, a modal BottomSheet (standalone or a switcher step), a modal Drawer, a Lightbox, MobileNav, or CommandPalette's dialog — the message reaches a persistent live region inside that dialog, which assistive technology hears while the modal is open, instead of the page-body region the modal hides; outside a modal nothing changes. Component and app code rendered inside a modal that calls `useAnnounce` is heard without any change to it. Delivery follows exposure, in top-layer order: a message sent as a switcher step hands over reaches the entering step, forward or back; a message sent as a modal BottomSheet closes, or just before an open Dialog is unmounted, waits while the leaving modal still covers the page and is delivered at its real close to whatever is exposed then — the Dialog it was opened over, or the page body — instead of being lost; a message a modal receives while a later modal covers it is not written and its region is clear before it is on top again. Busy controls inside a modal announce their busy start through the same region, including inside a native modal an app renders without Astryx; messages written to one region before the first is exposed are joined, and an identical repeat in the same frame is said once. The region's internal marker is `data-astryx-modal-live-region="polite"` or `"assertive"` (the busy region's former `data-astryx-modal-busy-region` is gone). Not in this change: CommandPalette's own result-count messages, Lightbox's own position and zoom messages, and Selector's and MultiSelector's selection and result-count messages in their `bottom-sheet` presentation are sent from the component that renders each dialog, above it, and still use the page-body channel while that dialog is open; each component's own change follows. This meets the in-modal delivery requirement in spec:AST-086 (FR14).
