[fix] `theme template` run from a folder inside a project reads its path from that folder within the project root, and with no path writes `theme.template.ts` at the project root, as its help says; a backslash in the path separates folders, as for `theme eject`. Outside any project (no `package.json` in the folder or above it) it still writes in the current folder, as released CLIs did; that is now deprecated (DEP-0030): when it writes the file it warns once on stderr in text mode, naming the fix (run it inside a project, or `npm init -y` first), and under `--json` it adds `meta.deprecations` instead. The next minor version refuses it. A stale `theme build --check` (and `experimental theme compile --check`) result carries `code: "ERR_THEME_STALE"` beside `upToDate: false`, the code it exits 1 with. A file at an `--out` path that the build did not write is left alone with its real reason and, when one exists, an `--out` path where no output of this build exists yet (a new folder when the theme's module beside it is taken); the build never suggests deleting it. `--out` into a folder the theme editor made, for a theme source outside that folder, still writes there as released CLIs did; that is now deprecated (DEP-0031): it warns once on stderr in text mode, naming the fix (build beside the source, or pass an `--out` outside the editor folder), and under `--json` it adds `meta.deprecations` instead. The next minor version refuses it.
