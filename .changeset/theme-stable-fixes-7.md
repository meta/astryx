[fix] `theme template` run from a folder inside a project reads its path from that folder within the project root, and with no path writes `theme.template.ts` at the project root, as its help says; a backslash in the path separates folders, as for `theme eject`; `astryx init --features theme`, run below the project root, writes `theme.template.ts` at that root too, because it uses the same template step. Outside any project (no `package.json` in the folder or above it) it writes in the current folder, as released CLIs did, and when it writes the file it warns once on stderr in text mode, naming how to write it at a project root (run it inside a project, or `npm init -y` first); `--json` stays silent. A stale `theme build --check` (and `experimental theme compile --check`) result carries `code: "ERR_THEME_STALE"` beside `upToDate: false`, the code it exits 1 with. A file at an `--out` path that the build did not write is left alone with its real reason and, when one exists, an `--out` path where no output of this build exists yet (a new folder when the theme's module beside it is taken); the build never suggests deleting it. The build-beside-the-source suggestion keeps `--icons-specifier`. `--out` into a folder the theme editor made, for a theme source outside that folder, writes there as released CLIs did, and warns once on stderr in text mode, naming how to keep the editor's folder to its own theme (build beside the source, or pick another `--out`); `--json` stays silent, and `--watch` prints it once per session, not on every rebuild.
