[experimental] `astryx experimental render`: a rendered file now explains itself to whoever opens it next. A note at its top names the CLI version and render format that made it, the page's path, the files it carries and the packages it rendered with, and gives the exact commands that get the source back and render it again; a short note after the embedded source repeats the way back. `--reverse` reports the render format, the CLI version (`renderedBy`), the packages and an explicit `--title` (`title`), and, for files this version renders, whether someone changed the markup after the render (`edited`, read as a browser reads the file, so a copy whose line ends changed on the way is not edited) with each text change (`edits`: what it was, what it is now, and the restored file and line that hold the old text, in a module or the JSON data it imports, also where it wraps across lines). A file in a newer render format than the CLI reads is refused with the new `ERR_RENDER_NEWER_FORMAT`, which names the CLI version that wrote it; a file that names a CLI version that is not a semantic version is refused as damaged, so no printed command carries it, and every path a printed command takes from a received file is quoted. The render format stays 1, so earlier CLIs keep reading the files this version writes, except for a file that carries an `.mts`, `.cts` or `.cjs` module, which says format 2 so that a CLI that reads render formats names the CLI that reads it; 0.7.16 and earlier refuse it as damaged.
