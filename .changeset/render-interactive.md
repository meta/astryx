[experimental] `astryx experimental render` now writes the page as a live app in one file: popovers, menus, dialogs, tabs, forms and every other control work as in the app. The file carries the page's own script, inline after the embedded source: the page's modules and the packages they use, bundled for the browser by esbuild. It paints the rendered markup first, then the script draws the live page over it. It is still one file, and the render adds no network request and no `eval`, so it works in a sandboxed frame that allows scripts, under a content security policy that allows inline scripts; a frame that blocks scripts shows the markup, and `--reverse` still gives the page back byte for byte. A link out of the file opens in a new tab, and a form submits even in a viewer frame that blocks form submission: the file fires the form's submit event itself. A page whose script cannot be built for the browser (a module it loads needs Node, say) is refused with the new `ERR_RENDER_SCRIPT`, which names the module. esbuild is a new dependency of the CLI, and only `experimental render` loads it, so no other command starts slower. The JSON adds `scriptBytes` and `scriptModules` to a render. When the page's script throws, in its render or in an effect (a frame that blocks storage, say), the file keeps showing its first paint. An image the page names by a path in a string, in `src` or `srcSet`, keeps showing once the script draws the page, and an image named in `srcSet` is carried too. A page file the page loads later (a dynamic import) that does not compile is refused as a static import is, with `ERR_RENDER_COMPILE` naming the file and line.
