[fix] `astryx template <name> <path>` and `astryx template --cdn <path>` accept an absolute path inside the project root, also through a symlinked project folder. It is written exactly as its relative path. An absolute path outside the project is still refused with `ERR_PATH_TRAVERSAL`. For `astryx template <name> <path>`, the receipt says the path was written as its relative path (`data.givenPath` in `--json`), and the refusal names a command that writes inside the project and the command that prints the source without writing anything. In a Next app whose `pageExtensions` include `tsx` (the default), the named path is one Next builds and serves: a page goes to the App Router folder (`app/<name>`, or `src/app/<name>`, inside the route group with the root layout when that folder has none of its own), or, with only the Pages Router, to the page file `pages/<name>.tsx`; a block goes to `app/components/<name>` with a root `app/` folder, `components/<name>` with only a root `pages/` folder, else `src/components/<name>`. Every other project gets `src/pages/<name>` and `src/components/<name>`. When that path exists or another page already serves its URL, the name becomes `<name>-2`, `<name>-3` and so on. The path is quoted in the command when a shell would read it otherwise, as with a route group folder. Next refuses to build when its `app` and `pages` folders are in different folders, and when two pages serve one URL. For `--cdn`, the receipt is unchanged, and the refusal names `astryx template --cdn cdn.template.html`.
