[feat] `astryx upgrade` rewrites the deprecated `swipeActions` and `swipeBehavior` props of `Item` and `ListItem` to `swipe={…}` where each entry is an object literal. It defines each swipe once with `createSwipe`. The definition goes to module scope when every value outside a handler is fixed at import: a literal, a JSX element, an import or a module `const`. It goes into `useMemo` in the enclosing component or hook when the options read its props or state. A function counts as one when it is declared or assigned under a capitalized or `use…` name, directly or through `memo` or `forwardRef`. Each entry with no `id` takes one named after its label or handler, else its side and place, with a TODO. On a `ListItem`, a handler that compares the row's `itemKey` value with `===` or `!==` takes it from `onActivate` instead. Where it cannot define a swipe once, it keeps `createSwipe` on the row and leaves a TODO. That covers options that read a map callback's value, a ref's `current` or a local assigned after its declaration. It covers a local they read at render when code sets, updates or deletes a property read from it. A method called on such a local counts too, and so does passing it to a call, naming it again, storing it or returning it. It also covers options that call or read at render something that is neither fixed nor one of the component's own props, state or locals. The codemod assumes that props, state and hook results are not changed in place, as React's rules and the React Compiler assume. Only an entry's `onActivate` runs when the action fires; any other callback in the options runs at render. On an `Item`, that TODO says an `Item` passes no `itemKey`. It reports, and leaves unchanged, a value whose entries it cannot see and a JSX spread that may carry the props.
