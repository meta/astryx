[perf] A `Tooltip`, and every component's tooltip (`Button`, `IconButton`, `Link`, `InfoTip`, `Avatar`, a field's `disabledMessage` and status tooltips, `SideNavItem` in the collapsed rail and others), now mounts its layer at its first hover, focus or tap instead of with its trigger. A table with a tooltip on every row mounts no closed tooltip layers, so such a page loads faster. Until the tooltip first mounts, the trigger's `aria-describedby` names a hidden copy of the tooltip text (a `hidden` element) rendered next to the trigger, so screen readers hear the description before the tooltip first shows. Once the tooltip mounts, `aria-describedby` names the tooltip's content and the copy is removed, so the text renders once and is read once. Components that build their tooltip with `useTooltip` (`Button`, `IconButton`, `InfoTip`, `Avatar`, a field's disabled reason and status icon, and others) and a `Tooltip` around plain text name the copy in server HTML. A `Tooltip` around an element, or with `anchorRef`, names it once the page hydrates; that includes the tooltips of `Link`, `StatusDot`, `Thumbnail`, `Table` row status and `SideNavHeading`. Tooltip content also renders from mount as that hidden copy, so a component inside it runs its effects before the tooltip first shows. `useTooltip`'s `describedBy` is the id of that description, not the tooltip element's id: code that looked up the tooltip with `document.getElementById(describedBy)` now gets the copy before the first show and the tooltip's content after it. A toggle-style trigger built on `show()` and `hide()` needs only `aria-describedby` and `aria-expanded`. Hover, focus and tap open the tooltip exactly as before.
