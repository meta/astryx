[fix] `astryx theme build` now writes a built theme module that loads in any bundler and in plain Node. A local module the built module imports (an icon registry, a component icon slot value, or the helpers they import) that is TypeScript or JSX is compiled to JavaScript named after its source (`icons.tsx` → `icons.tsx.js`, so an import of `./icons` still finds the source) under the output folder: beside the outputs while every compiled module sits in the theme's folder; when any sits outside it (a shared helper), every module is mirrored under the output folder from the folder that holds them all, never in the source tree. Each local import names its file with its extension: `import { icons } from './icons'` with `icons.tsx` beside the theme becomes `import { icons } from './icons.tsx.js'`. A compiled module is an output of its own source: themes built in one command that import the same module share it. Before, the built module kept the TypeScript import, so an app whose bundler does not compile TypeScript from `node_modules` (a plain Next.js app) failed to build after it added the theme. The compiled modules carry the build header, `--check` compares them, and a file of your own at a compiled module's name is never replaced (that import stays as written). A theme with no local module writes the same outputs as before; package imports stay as they are. `--family` builds compile each member's TypeScript registry the same way, each to its own compiled file.
