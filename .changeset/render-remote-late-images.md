[experimental] `astryx experimental export`: an https image the page shows only later (after a click, in the next view) is carried too, when the page's own code writes its address whole. That means an address an element shows as an image (an `<img>`'s or an `<input>`'s `src`, an `<img>`'s or a `<source>`'s `srcSet`, a `<video>`'s `poster`), written there or in a variable the same file reads there (`const logoUrl = '…'` with `<img src={logoUrl}>`); an address whose path ends in an image extension; or one a name says is an image: a component's or an object's `src`, `srcSet` or `poster`, or a property or attribute one of whose words names an image (`avatarUrl`, `cover_image`; not `logoutUrl`). An address written only where an element takes it for something else, such as an `<iframe>`'s or a `<video>`'s `src`, is not fetched, even when its path names an image, and the file puts no carried data there; nor is one whose path names a type that is never an image (`clip.mp4`). It is fetched with the same rules and limits as an image in the first paint, and listed in `remoteImages`. The page's script keeps every address as the page wrote it, so a link, a text, a comparison and the URL API read the page's own address. Where the browser takes an image's address (the same attributes, or a CSS `url()` in a style the script sets), the file gives it the carried data instead, so the image shows offline. An address the code gives a fragment gets the carried image too; one it gives another query (`${hero}?w=640`, or the URL API's `searchParams`) can name another image, so the file asks the network for it. A link's address written in `href`, directly or through a variable that only links read, is never fetched, even when it names an image file. An address that counts only by a name (`imageUploadUrl`, an object's `src`) can be an API's or a player's: when its answer is another type (an API's JSON, a page), `remoteImages.failed` lists it with why, and the fetch adds no warning. Any other address the script draws later warns when its fetch fails, as in the first paint. No other address is fetched. An image address the code builds from parts where a whole one would count (a template or `+` chain that starts with `https://`) cannot be carried: a `remote-asset` warning names it, its file and its line. An address built any other way is neither carried nor warned.
