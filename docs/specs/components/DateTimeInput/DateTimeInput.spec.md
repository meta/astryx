# DateTimeInput component contract

## Contract at a glance

| Area                    | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public contract         | One controlled ISO date-time value presented through coordinated date and time segments; `presentation` selects Astryx, native, or adaptive picker surfaces. `calendar` selects the calendar system the date segment shows on every surface (`spec:AST-111` FR2). `onEntryErrorChange` reports each typed date rejection as a `DateInputEntryError`, and with it a caller `error` status words the rejection (FR11, AR5). `entryErrorBehavior` sets when both segments reveal their own rejections (`spec:AST-117` FR1).                                                                                                                                                                                                        |
| Behavior                | Date and time changes emit one combined value; clear emits `undefined`; controlled empty state remains empty in every rendered picker. The pointer date segment reads and writes typed dates in the resolved calendar and reports a typed date only when it is complete (FR11). With a calendar other than `gregory` or `iso8601`, a presentation that would show native controls shows the popovers on a fine pointer and the bottom sheet on a coarse pointer, and the bottom sheet shows months of the calendar (FR12).                                                                                                                                                                                                      |
| End-user impact         | People selecting a date and time see one value reflected consistently in the closed field and the active picker, including after clearing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Builder impact          | A caller that relied on the `12h` hour-format default under a 24-hour locale passes `hourFormat="12h"` to keep twelve-hour time text. A per-user 12/24-hour preference goes on the provider locale as a `-u-hc-` extension (`en-US-u-hc-h23`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Compatibility/readiness | The `hourFormat` default is the provider locale's hour cycle (`12h` for `en`/`en-US` and with no provider); every other released default, API, and DOM shape holds. The presentation matrix and deprecated `nativePicker` mapping follow `spec:AST-043`. Fixed segment height, typed-time prefix commits, busy paint, and caller handlers while disabled are listed under Current-state impact. `calendar` is additive with a Gregorian default; typed Gregorian dates follow FR11, and calendars that need `Temporal` fall back to Gregorian where it is missing (the `spec:AST-013` FR12 exception). `onEntryErrorChange` is additive; without it, a typed date rejection's message replaces a caller `status` as AR5 states. |
| Review checks           | Reject competing picker selection, date/time output that is not one valid combined value, presentation precedence drift, lost per-segment fallback, broken segment accessibility, an unfinished entry flagged as rejected, or a rejection revealed before commit under `'blur-or-enter'`.                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Intent

DateTimeInput presents one controlled date-time value as coordinated date and time
segments under one field label. Depending on `presentation`, the segments use
Astryx popovers, one coordinated bottom sheet, browser or operating-system inputs,
or pointer-adaptive combinations of those surfaces.

## Compatibility and migration

- Released default preserved: `yes`, except `hourFormat`, which follows the
  provider locale's hour cycle (`12h` for `en` and `en-US`, the released
  default with no provider) and shares TimeInput's locale time text
- Compatibility class: default change for non-English-US locales; additive
  `calendar` prop with a Gregorian default; typed Gregorian dates fire
  `onChange` only for complete input (FR11); a non-Gregorian calendar replaces
  native controls with the Astryx surfaces for the pointer, and an explicit
  `native` warns in development (FR12); the additive `onEntryErrorChange` prop
  changes nothing for a caller that omits it (AR5); existing types, callbacks,
  roles, and exports remain stable. A provider locale with a `-u-ca-` keyword keeps
  Gregorian dates (`spec:AST-111` DEC-2); set `calendar` to choose one.
  `entryErrorBehavior` is additive; its default, `'complete'`, is the shipped
  behavior (FR15, `spec:AST-117`). An unfinished entry shows no rejection,
  rejected text stays on blur, a rejection shows a message, and Enter commits
  the time segment and still submits a form (FR16): an accessibility behavior
  fix that ships in a patch (`spec:AST-017` FR53, `spec:AST-118`).
- Controlled/uncontrolled behavior: DateTimeInput remains controlled; `undefined`
  represents no committed date-time value
- Migration decision: none; picker presentation and deprecated `nativePicker`
  compatibility remain governed by `spec:AST-043`

Consumer migration instructions belong in consumer docs and release notes.

## Ownership boundary

**Owns**

- Coordinating date and time segments into one controlled ISO date-time value.
- Choosing and composing the date and time surfaces selected by `presentation`.
- Applying component-local date-time bounds, date constraints, time precision,
  typed-time stepping, and optional preset-time behavior.
- Emitting `onChange` before an optional optimistic `changeAction`.
- The disabled-reason Tooltip composition, which `family:input-fields` assigns
  to the member.

**Does not own / non-goals**

- Field label, description, status, and clear-button presentation —
  owned by Field under `family:input-fields` (shared owner section) and
  `component:FieldStatus`.
- Calendar-grid rendering and date-cell interaction — owned by
  Calendar.
- Popover and sheet hosting or dismissal — owned by the composed layer components
  and `family:overlay-dismissal`.
- The sheet wheels' rest, motion, scroll input, and look — owned by
  `component:DateInput` (FR13–FR15, DEC-1, DEC-2).
- Cross-component picker-presentation vocabulary and deprecated-prop mapping —
  owned by `spec:AST-043`.

### Allowed variation

- **AV1 — Surface.** The caller may force Astryx, native, or bottom-sheet surfaces,
  or choose an adaptive presentation within the current system-spec matrix.
- **AV2 — Date and time formatting.** Locale, hour format, seconds, week start,
  month count, and preset cadence may vary through their documented inputs.
- **AV3 — Optional field support.** Clear, loading, status, disabled reason,
  description, and label visibility may be omitted without changing value ownership.

| State                       | Required invariant                                                                                                                                                                                          | Allowed variation                          |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Empty                       | Both segments and every active picker expose no committed selection.                                                                                                                                        | Placeholder and selected surface.          |
| Date-time value             | Date segment, time segment, and active picker reflect the same committed value.                                                                                                                             | Locale, hour format, and time precision.   |

### Transformation and precedence order

- **ORD1 — Picker selection.** Resolve `presentation` before deprecated
  `nativePicker`; with a calendar other than `gregory` or `iso8601`, use
  `adaptive-bottom-sheet` in place of `native` and `adaptive-native` (FR12);
  apply pointer adaptation, then apply only the per-segment native fallbacks
  permitted by `spec:AST-043`.
- **ORD2 — Value mutation.** Validate the proposed segment value, combine it with
  its committed counterpart, call `onChange`, present the optimistic combined
  value, then run `changeAction` in a transition.

### Performance and resources

- **PR1 — Preset options.** The time listbox mounts option nodes only while open;
  omitted preset cadence leaves no listbox nodes or combobox semantics.

Current measurements belong in the audit record; this subsection owns only
durable constraints and their verification target.

## Accessibility contract

- **AR1 — Field naming.** The date segment is named by the field label; the time
  segment uses `timeLabel` or a localized label-derived fallback. Description,
  status, and disabled-reason text remain referenced from both segments.
- **AR2 — Picker semantics.** The Astryx date segment is a combobox controlling a
  dialog; the optional preset-time field is a combobox controlling one listbox.
  Omitted preset cadence leaves the time field without combobox semantics.
- **AR3 — Keyboard and focus.** Documented keyboard activation, date-popover
  dismissal, preset-time navigation, focus containment, and focus restoration
  remain operable on their active surfaces.
- **AR4 — Required, invalid, busy, and disabled.** Both editable segments expose
  applicable required, invalid, busy, and disabled states; a focusable disabled
  reason never re-enables mutation. A segment's invalid state follows FR15.
- **AR5 — Typed-date rejections and the calendar.** Unreadable text, a date the
  calendar does not have, and an out-of-range date each announce a different
  catalog message from the date segment, and each also shows it as the field's
  error status (FR16), in place of a caller `status` while the rejected text
  stays (`spec:AST-111` AR3). With `onEntryErrorChange`, a caller `error`
  status with a message shows and announces in place of the field's message,
  and a `warning` or `success` status never replaces a rejection, as
  `component:DateInput` AR3 states. The field status announces itself, and the
  date segment's alert carries only the rejection message that no status
  announces, so each message is announced once; a rejection that starts under
  an unchanged caller error message is announced once by that alert, as
  `component:DateInput` AR3 states.
  The pointer date segment's description names the calendar only when its
  resolved calendar differs from the provider's resolved calendar, else
  `gregory`, with `gregory` and `iso8601` as one calendar, both compared after the Gregorian fallback for a runtime without
  `Temporal`. With a calendar other than `gregory` or `iso8601` and no caller
  `placeholder`, the empty focused segment shows an example date in the
  calendar's numeric pattern; a caller `placeholder` shows in every state and
  replaces the hint. The example date is today when the field accepts it, else
  the nearest date it accepts (`spec:AST-111` AR2).

The calendar-toggle target reflects expanded or collapsed state. The time-options
listbox owns option rows through the `date-time-input-time-option` target; the
leading clock glyph uses `date-time-input-clock-icon`.

### `spec:AST-013` FR12 exception — calendars that need `Temporal`

- **Capability:** typed date entry, committed date text, and the bottom sheet's
  Date panel in calendars other than the Gregorian, Buddhist, Minguo, and
  Japanese calendars, which need the runtime's `Temporal`.
- **Reduction:** where `Temporal` is missing, as in Safari on macOS and iOS, the
  date segment reads, writes, and shows Gregorian dates, its presentations
  resolve as they do for `gregory`, and it warns once in development, naming a
  polyfill (`spec:AST-111` FR5). An application that loads a `Temporal` polyfill
  gets the full calendar. When a server and a browser use implementations of the
  Chinese or Dangi calendar that disagree on a month start, React renders the
  differing text again on the client (`spec:AST-111` FR19).
- **Preserved obligations:** `spec:AST-013` FR7 and FR8, and FR9 outside that
  case of the Chinese and Dangi calendars. The Gregorian date and time segments
  keep every interaction, label, and announcement, and Buddhist, Minguo, and
  Japanese entry works without `Temporal`.
- **Evidence:** real Chromium and Firefox typing in calendar fields with native
  `Temporal`, with `Temporal` removed and a polyfill loaded, and with
  `Temporal` removed and no polyfill, through the shared DateInput field; the
  shared bottom sheet in real Chromium, Firefox, and WebKit in the same three
  modes.
- **Owner:** `nynexman4464`.
- **Review condition:** Safari ships `Temporal`.

## Current-state impact

- **Fixed height (FR5).** Segments hold the fixed shared element height instead
  of growing with a set text size, against `spec:AST-102` FR4.
- **Typed-time prefix commits (FR7).** The typed time field commits a parsed
  prefix, so a typed time can commit a different time, against
  `architecture:internationalization` INV8.
- **Entry error behavior (FR15).** The field has no `entryErrorBehavior`, so
  both segments always reveal rejections as `'complete'` does.
- **Rejected entries (FR16).** The time segment marks every draft that is not
  an in-range time invalid and announces it on each keystroke while the text
  only turns secondary, and blur reverts it; unreadable text in the date
  segment does the same and reverts on Enter or blur; and Enter in the time
  segment commits nothing unless its preset-time list is open (`spec:AST-118`
  FR1–FR5, FR9).
- **Busy paint (FR9).** A busy field that is not disabled takes the disabled
  half-opacity paint, against `spec:AST-085` FR6.
- **Caller handlers while disabled (FR9).** Caller DOM handlers on the date
  segment, such as `onKeyDown`, still run while disabled, against
  `spec:AST-085` FR2.
