# Calendar component contract

## Contract at a glance

| Area                    | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public contract         | `Calendar` and `CalendarProps` are exported from `@astryxdesign/core/Calendar`; `mode` selects a single date or a range, with `value`/`defaultValue`/`onChange`, bounds, constraints, span limits, focus date, display options, and an optional `calendar` (`CalendarSystem`). Every value stays a Gregorian ISO date. The public `useCalendarDays` and `useCalendarNavigation` hooks take an optional `calendar` too (FR11).                                                                                                                      |
| Behavior                | One or two months of the resolved calendar system render as day grids under weekday headers (DD1); a day is picked by pointer or keyboard; each month grid holds at most one roving Tab stop, which arrow, Home/End, and Page keys move, following the reading direction. Page keys step calendar months, and with Shift calendar years.                                                                                                                                                                                                           |
| End-user impact         | A keyboard or screen-reader user meets a named month grid, moves through it by day, week, and month (and year with Shift and a Page key), and hears each day's name, selection, today marker, and disabled state, in the calendar the application chose.                                                                                                                                                                                                                                                                                           |
| Builder impact          | Optional: set `calendar` on the Calendar or its provider; for a calendar that needs `Temporal`, load a polyfill where the runtime lacks it.                                                                                                                                                                                                                                                                                                                                                                                                        |
| Compatibility/readiness | The `calendar` prop is additive and the default stays Gregorian. A provider locale with a `-u-ca-` keyword keeps Gregorian dates (`spec:AST-111` DEC-2); set `calendar` to choose one. Calendars that need `Temporal` fall back to Gregorian where it is missing (the `spec:AST-013` FR12 exception). The month buttons use native `disabled` at a bound and scale under reduced motion, a key-moved Tab stop can go stale, and the Calendar grows wider than a phone screen at the largest text sizes; all are listed under Current-state impact. |
| Review checks           | Reject a day grid without `role="grid"` or a name, two days in one month holding a Tab stop, an arrow key that stops following the reading direction, a selection or today state carried only by colour, a weekday header cut to a fixed number of characters, or a header row mixing abbreviated and short names.                                                                                                                                                                                                                                 |
| Governing rules         | DD1 for the weekday headers; `architecture:public-component-api/INV1,INV5–INV8`; `architecture:component-theming-surface/INV3–INV7`; `spec:AST-020/FR15`; `spec:AST-085/FR1, FR4`; `spec:AST-102` FR4; `spec:AST-111` FR1–FR8, FR20, AR1; `spec:AST-013` FR12; `design:bidirectionality` DR6; `design:reduced-motion` DR1; `architecture:internationalization` INV8.                                                                                                                                                                               |

This table is a review projection; the body below is authoritative.

## Intent

Calendar lets a person pick a date or a date range by looking at whole months. It
owns the month grid, its navigation, selection and range semantics, and the
keyboard model that moves through days; date fields compose it.

## Compatibility and migration

- Released default preserved: `yes` — without a `calendar` prop or a
  provider calendar, the grid shows Gregorian months — except DD1: `no`,
  since Calendars in locales whose abbreviated names fit (English among them)
  show those names, with no prop to keep the short names
- Compatibility class: additive optional `calendar` prop and hook option; no
  default, export, or DOM structure change; the weekday header text follows DD1. A provider locale
  with a `-u-ca-` keyword keeps Gregorian dates (`spec:AST-111` DEC-2); set
  `calendar` to choose one
- Controlled/uncontrolled behavior: `value` with `onChange` is controlled;
  `defaultValue` starts internal state
- Migration decision: none

Consumer migration instructions belong in consumer docs and release notes.

## Ownership boundary

**Owns**

- The month grid: its weekday column headers, week rows, day cells, outside days,
  week numbers, and variable row count.
- Month navigation, the focused day, and the keyboard model that moves it.
- The calendar months it lays out, their labels, and month and year steps in
  the resolved calendar system.
- Single and range selection semantics, bounds, constraints, and span limits.

**Does not own / non-goals**

- The text field, popover, and bottom sheet that present a Calendar — owned by
  DateInput and its siblings.
- Time of day — owned by DateTimeInput.
- Calendar resolution and the `Temporal` boundary — owned by `spec:AST-111`
  FR1, FR2, and FR5; calendar arithmetic — owned by `Temporal`.
- `handleRef`, `onFocusDateChange`, the opening month inside the `min`/`max`
  window, `weekStartsOn`, and `numberOfMonths` clamping — shipped and covered
  by the consumer docs and tests, uncontracted here beyond FR1–FR7.

### Allowed variation

- **AV1 — Month layout.** Row count, outside days, and week numbers may vary by
  props without changing FR1–FR5.
- **AV2 — Internal state.** The focused-day and selection state may be stored in
  any private shape.

### Transformation and precedence order

- **ORD1 — Pick.** Disabled check → mode-specific selection update → `onChange`.
- **ORD2 — Focus movement.** Key → reading-direction mapping → target day → month
  navigation if needed → focus.

### Performance and resources

- **PR1 — Render-owned grid.** Day cells render from props and state; focus
  movement reads the grid's cells on demand; day buttons share the press
  controller's window and document listeners; Calendar owns no observer.

## Accessibility contract

- **AR1 — The day grid adopts the APG Grid pattern** (`spec:AST-020/FR15`), as
  one composite control: each month is `role="grid"` with an accessible name,
  weekday `columnheader` cells, week `row`s, and day `gridcell`s that carry
  `aria-selected` when selected or in range and hold one `button` named by the
  full date plus its selection or range role (selected, range start, range end,
  or in range), which exposes `aria-current="date"` for today and `aria-disabled`
  when disabled; one day button holds the Tab stop — the selected day in
  `single` mode when it is in that month and enabled, else today when it is in
  that month and enabled, else the month's first enabled day; a month with no
  enabled day has no Tab stop. Implementation gap: once a key move (arrow, Home,
  End, or Page key) has placed the stop, a later pointer pick can leave it
  there (always when the picked day comes later in the grid), and when every
  day of that month becomes disabled it stays on a disabled day.
  ArrowLeft and ArrowRight move by a day following the reading direction
  (`design:bidirectionality` DR6),
  ArrowUp and ArrowDown by a week, Home and End to the first and last enabled day of the
  week, PageUp and PageDown by a calendar month, Shift+PageUp and
  Shift+PageDown by a calendar year (a named exception, as in the APG date
  picker dialog; a day the target month lacks clamps to its last day; FR9),
  and Enter or Space picks the focused day;
  an arrow skips a day disabled by a constraint and continues in the
  same direction, crossing the month edge when it must; an arrow or Page key whose target
  lies past `min` or `max` changes nothing and keeps focus where it is, and
  so does an arrow whose direction has no enabled day within a year; a page
  onto a day disabled by a constraint focuses that month's first enabled day
  instead, and changes nothing when that month has no enabled day. Spoken
  dates (day-button names, grid names, and announcements) use the calendar
  that the grid shows (`spec:AST-111` AR1).

## Family and system relationships

- `spec:AST-020/FR15` decides which APG parts a component adopts; the day grid
  adopts the Grid pattern because it already acts as one composite control.
- `spec:AST-085` owns disabled focusability; days meet it and the month
  buttons do not (FR6).
- `component:Button` renders the month buttons.
- `spec:AST-111` owns calendar selection, the supported calendars, Gregorian
  ISO values, and the `Temporal` boundary; FR8–FR10 and AR1 project its FR4,
  FR6–FR8, and AR1 onto the grid.
- `component:DateInput`, `component:DateRangeInput`, and
  `component:DateTimeInput` pass their popover Calendar the calendar their field
  text uses (`component:DateInput` FR20, `component:DateRangeInput` FR6).

### `spec:AST-013` FR12 exception — calendars that need `Temporal`

- **Capability:** calendars other than the Gregorian, Buddhist, Minguo, and
  Japanese calendars, which need the runtime's `Temporal`.
- **Reduction:** where `Temporal` is missing or does not support the calendar,
  as in Safari on macOS and iOS, such a calendar resolves to `gregory` before
  the first render and warns once in development, on the server and in the
  browser, naming `temporal-polyfill/full/global` (`spec:AST-111` FR5). An
  application that loads a `Temporal` polyfill gets the full calendar. A server
  without `Temporal` renders Gregorian markup, which a browser with `Temporal`
  does not match, so a server-rendered application loads `Temporal` on the
  server too. Month starts in the Chinese and Dangi calendars follow the
  runtime's `Temporal`; a server and a browser whose implementations disagree on
  a month start render that month differently, and React renders it again on the
  client during hydration (`spec:AST-111` FR19). Day and month names follow the
  month and day that the grid shows in every case.
- **Preserved obligations:** `spec:AST-013` FR7 and FR8, and FR9 whenever the
  server and the browser resolve the calendar the same way, outside the
  case of the Chinese and Dangi calendars. The Gregorian grid keeps
  the primary task, accessibility, Gregorian ISO values and callbacks, and
  repeated use; nothing throws; a server and a browser that both have
  `Temporal`, or both lack it, render the same markup.
- **Evidence:** real Chromium and Firefox with native `Temporal`, with
  `Temporal` removed and a polyfill loaded, and with `Temporal` removed and no
  polyfill; server render and hydration with `Temporal` on both sides, on
  neither side, and on the browser only.
- **Owner:** `nynexman4464`.
- **Review condition:** Safari ships `Temporal`.

## Current-state impact

- **Width at the largest text sizes (FR2).** At text sizes near 275% and
  310% of the theme's sizes, such as a larger browser default font size
  (iOS AX4 and AX5 once text follows Dynamic Type), the Calendar grows wider
  than a phone screen, so the last weekday column is reached only after a
  sideways scroll. Each day still owns its own taps.
- **Stale Tab stop (FR3, AR1).** After a key move places the Tab stop, a later
  pointer pick can leave it there (always when the picked day comes later in
  the grid), and when every day of that month becomes disabled it stays on a
  disabled day, so Tab can land on an unselected or disabled day.
- **Month buttons under reduced motion (FR6).** The Previous and Next buttons
  scale on a press when the person prefers reduced motion, as `component:Button`
  FR15 records, against `design:reduced-motion` DR1.
- **Month buttons at a bound (FR6).** Previous and Next become natively
  disabled at `min` and `max`, so a keyboard user on the button that reaches the
  bound loses focus, against `spec:AST-085` FR1 and FR4.
